# 轻微循环 GIF 与九宫格切分

## 动画方式

用户已认可“贴纸整体轻动”的本地 GIF 效果，可以采用每个角色独立的小幅平移、旋转和轻微缩放。它保留原有造型、服装和表情，不应被描述为重新生成的眨眼、摆手或肢体动作。用户明确要求肢体动作时，先确认当前是否存在支持该能力的动画工具；不能用整张图摇动冒充局部动作。

默认每周期约 1 秒、20 帧、每帧 50 毫秒、无限循环。每个人物的位置锚点固定在自己的格子里，以周期函数控制几像素的位移、约 1–3 度旋转或约 1–3% 的缩放。这些是轻动起点，可按图片尺寸调整。不同人物使用适合其情绪的节奏，不移动镜头或整体画布。不要把上一轮某个人物的动作机械绑定到同一格的新人物。

原始人物、文字、道具作为完整贴纸组一起保留。先为动作预留透明空间；旋转时使用扩展画布，再放回足够大的固定单元，不能用不扩展的旋转裁掉角落。若缩放，保持原宽高比。所有帧的完整动作范围必须在格内，不与其他格重叠。首尾采用连续周期相位，避免重复端点导致停顿。保持九宫格顺序和布局。

## 用户确认的动画提示词

> 图中的小人在固定位置轻微移动，像 GIF 表情包一样，不要互相遮挡，保持每个小人独立的动作。每个小人的动作持续时间约为 1 秒，循环播放。不要改变原本的人物造型、服装、表情和九宫格位置。所有人物只进行适合表情包的轻微动作，例如摇头、摆手、哭泣、耸肩、点头、震惊后退、得意晃动等。背景保持透明，确保每个角色之间互不遮挡。整体动作简单、循环自然，不要出现镜头运动，不要改变构图。输出适合社交平台使用的短循环动画。

使用上述提示词时按工具真实能力实现，并如实说明采用的动画方式。它不意味着在没有视频生成工具时声称已生成新肢体动作。

## 真实透明与导出

- 先检查原文件的 Alpha 或透明索引。灰白棋盘格可能是画进图片的背景；把 RGB 改成 RGBA 并不会去掉背景。
- 如果没有真实透明，先处理背景再制作或切分。遵循当前工具规则；用户授权本地抠图时才使用相应方式。浅色背景处理不得全局删除白色，否则会破坏衣服、眼睛、文字和道具。
- PNG 保留原 Alpha，包括半透明发丝边缘。GIF 只有单级透明，应保留独立透明调色板索引，避免将黑色轮廓误设成透明。
- GIF 使用正确的帧处置方式，防止运动拖影。检查深色和浅色预览中的边缘，不能用新增白边、描边或阴影掩盖残边。原图已有的卡通线条属于人物内容，应保留。
- 不把试稿中出现过的浅色残边作为质量标准；发现残留应修正或明确说明。未给具体社交平台时，不声称已经符合其上传大小限制。

## 精确切分 9 张 PNG 与 9 个 GIF

按从左到右、从上到下编号 01–09。静态与动态编号对应同一主题。

1. 在真正透明的格间空隙中确定分割线。名义上的宽高三等分仅作为搜索起点，不能在人物、文字、道具或动作边缘上强切。每个分区应完整包含一个贴纸组，不混入相邻贴纸碎片。
2. GIF 先解码成完整合成帧，计算所有帧非透明范围的并集；根据整个周期选取分割线。所有帧使用相同裁切框，不能逐帧紧裁导致位置跳动。
3. 保留透明留白和完整内容，不拉伸、不添加白底、描边或阴影。分割线无安全空隙或人物已在母版边缘截断时，先修复母版，不能靠加透明边补回缺失内容。
4. PNG 导出九个 RGBA 文件；GIF 导出九个真正的动画文件，保留源动画的时长、帧时序和循环设置。不得把 GIF 的第一帧当作动态交付。
5. 检查数量、顺序、透明度、每个主体及游离符号的归属，动态还要检查全周期完整性、首尾衔接和无拖影。

## 可复用切分脚本

依赖 Python 与 Pillow。以下命令中的路径是占位符，替换成当前素材的真实路径：

```text
python scripts/split_grid.py <透明九宫格.png> <新的PNG输出目录>
python scripts/split_grid.py <透明九宫格.gif> <新的GIF输出目录>
```

脚本以所有帧 Alpha 并集查找三等分附近的透明分割线，将 01–09 保存到指定素材目录，裁切记录统一保存到其同级 `config/<素材目录名>-manifest.json`（标准目录对应 `config/png-manifest.json` 与 `config/gif-manifest.json`，其中文件路径相对于 config 目录），不抠图、不缩放，也不覆盖已有结果。若没有透明背景、没有安全分割线、出现空格或外边界接触内容，会停止并要求检查源素材。此时不要降低透明阈值来跳过真实的人物边缘。

自动分割后仍须目视检查：脚本不能判断游离爱心、文字或道具属于哪一个人物。必要时先重新排版母版或使用经过检查的固定裁切框。不要复用某张历史图片的像素边界作为通用坐标。

## 交付

完整任务输出静态九宫格、9 张独立 PNG、动态九宫格和 9 个独立 GIF。目录建议为 `png/01.png` 至 `09.png` 和 `gif/01.gif` 至 `09.gif`。可另打包 ZIP 方便下载；预览九宫格不能替代独立文件。用户只要求某类结果时，按其范围交付。

## 输出文件归类

所有随成品产生的配置、参数、切分清单和验证记录统一放在交付根目录的 `config/` 文件夹。`png/` 只放 PNG 图片，`gif/` 只放 GIF 动画，不在其中混放 JSON、YAML、TOML 或其他配置记录。PNG 与 GIF 的配置分别命名，避免覆盖。ZIP 打包时也保留此结构。

```text
交付目录/
  png/01.png … 09.png
  gif/01.gif … 09.gif
  config/
    png-manifest.json
    gif-manifest.json
```

本规则针对生成结果中的辅助文件。技能自身的 `SKILL.md`、`agents/openai.yaml`、脚本和参考资料继续保留技能规范要求的位置。
